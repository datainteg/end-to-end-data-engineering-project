# Voiceover recording pack

Nine clean English scripts are supplied, matching the planning folder's English default. Each `.txt` file contains spoken words only. Screen actions and technical warnings belong to [the recording plan](../RECORDING.md), not the narration input. These scripts can be recorded by the presenter or pasted into a voice service of their choice; no voice-service account or paid generation is used here.

Save recorded originals in the repository's root `voiceover/` folder, which is ignored; **these public text files remain tracked**. Prefer WAV at a consistent sample rate, record without music baked in, and retain unedited originals. Record one chapter per clip. Keep any retries as separate take files until selecting the final take.

Delivery: calm, clear, practical, with emphasis on “one order line,” “selected attempt,” and “committed.” Technical names remain in English. Pronounce SQL as “sequel” or “S-Q-L” consistently; JDBC as “J-D-B-C”; SCD type two as “S-C-D type two”; IAM as “I-A-M”; PySpark as “pie spark.” Say ₹1,200 as “twelve hundred rupees,” not twelve hundred paise.

Cloud passages use conditional/code-review wording because no deployment evidence exists yet. Adapt only after recording actual cloud results. The complete presentation target is 25–35 minutes, including demonstrations; narration duration must be measured after recording. Do not generate timestamped captions from the estimated chapter table.
